# airtime-call-tracker-extension: правила работы

Прочитай целиком перед правками.

## Ветки и PR — обязательно

Правило владельца (2026-10-06), общее для всех наших репозиториев; сводка и состояние
по репозиториям — `mg-srv-machine/DEV-RULES.md`.

1. Никогда не коммитить и не править `main` напрямую. Ни в одном режиме, даже
   «мелкая правка» и даже «починить срочно, потом разберусь».
2. Работа — в топик-ветке от `develop`: `feat/…`, `fix/…`, `chore/…`.
3. PR идёт в **`develop`**. Merge в `develop` — человек или ассистент по прямой просьбе
   владельца.
4. `main` двигается только промоутом `develop` → `main` через отдельный PR
   (релиз). Этот PR мержит **только человек**.
5. Откат — `git revert -m 1`, не `reset --hard` по живой ветке.

```
топик-ветка ──PR──► develop ──PR(релиз, мержит человек)──► main
```

Технической защиты веток на GitHub нет: дисциплина держится на этом файле и на ревью.

Прогон тестов проекта (см. README/RUNBOOK). Зелёные тесты — условие merge; на каждый найденный баг — регрессионный тест.
